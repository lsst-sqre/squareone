'squareone': patch
---

A signed-in user no longer sees "Log in", a missing Apps menu, or the wrong Portal and Notebooks entries after a full page load or a back/forward navigation of a route behind a Phalanx `GafaelfawrIngress`, such as `/times-square` and `/admin`. Gafaelfawr strips its own session cookie from requests crossing such an ingress, so the root layout's server-side auth prefetches got a 401 there and hydrated the user as anonymous, which the browser then kept. The prefetches now read the delegated internal token the ingress sends in `X-Auth-Request-Token` and present it to Gafaelfawr as a bearer token: user info is prefetched that way, the user's scopes are prefetched from the token's `token-info` (on plain-ingress routes they still come from the same login-info request as before), and login info, which is cookie-only, is left for the browser to fetch on those routes. This needs the ingress to request a delegated token (`config.delegate.internal.scopes`, covering every scope the UI gates on); an ingress that does not is logged as a warning once per process and falls back to the previous behaviour. The header nav, homepage hero, Apps menu, user menu's Admin link, and the admin section's gates and sidebar now read the user's scopes from a new app-level `useUserScopes` hook (`src/hooks/useUserScopes`, which attaches the Sentry reporter with `user-scopes` tags, and which the Biome `noRestrictedImports` rule requires over the package hook) instead of from login info. The development server's mocked Gafaelfawr accepts `gt-dev-delegated-token` as a bearer token on `/auth/api/v1/user-info` and a new `/auth/api/v1/token-info` mock, so the delegated path can be exercised locally by sending the ingress headers; see the development docs.
