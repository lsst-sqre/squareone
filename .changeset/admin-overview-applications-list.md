Correct the `/admin` overview's Applications section. It was a table that joined each Phalanx application to the Repertoire UI and API services of the same name, plus a hand-maintained alias map, but discovery's `applications` list and its `services` maps are separate namespaces: many services belong to no application of the same name, so the joined rows were misleading. The section is now a compact, alphabetical, multi-column list of the enabled applications with a count, each linking to its page in the Phalanx documentation (`https://phalanx.lsst.io/applications/<name>/`), and it says "Service discovery lists no applications." when discovery lists none. The services now have a section of their own: a new Services table, after the Applications list, lists every UI and API service in discovery's `services.ui` and `services.internal` maps, with sortable Service and Kind (`UI` / `API`) columns and a detail row of each service's title, URL, required scopes, and Documentation and OpenAPI links. A filter narrows the table by service name or title with a live count ("3 of 21 services"); under Repertoire 2.x a row shows just the service's URL (and its OpenAPI link, if any), and with no services the section says "Service discovery lists no services." The overview's sections are now Environment, Operator links, Applications, Services, Datasets, and InfluxDB databases.
