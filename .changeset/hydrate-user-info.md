The header no longer shows "Log in" to a signed-in user while the page loads. The root layout now also prefetches the user's Gafaelfawr user info on the server (forwarding the request's session cookie, as it does for login info) and hydrates it, so the server-rendered header already shows the user's menu with their username, and the first render in the browser keeps it. An anonymous visitor's user info hydrates as empty, so they see "Log in" from the start and never a menu. The log-in control no longer forces "Log in" until after the first client render, and the user menu now reads the username from the same hydrated user-info query instead of `useGafaelfawrUser`, so the browser makes no separate `/auth/api/v1/user-info` request on page load. As with login info, every part of the app that reads user info (the header, the sign-in gate on settings and admin pages, and the token, session, and quota settings pages) now goes through a new app-level `useUserInfo` hook in `src/hooks/useUserInfo`, which attaches the Sentry reporter and its `user-info` tags, and the Biome `noRestrictedImports` rule now also rejects importing `useUserInfo` from `@lsst-sqre/gafaelfawr-client` directly in app code. Pages behind the sign-in gate now render their content on the server for a signed-in user rather than a loading placeholder.
